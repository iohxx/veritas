# Verification rules and replay

The input validator rejects malformed jobs before retrieval or inference. Source records separate accessible, usable and supports_claim. Store URL, final URL, retrieval time, SHA-256, content type, snapshot and extracted text. HTML script/style content is excluded; no scripts are executed. UTF-8 text extraction is bounded and may truncate; original bytes remain in snapshots.

Deterministic operations: add, subtract, multiply, divide, percentage_change, mean, ratio, compare and fixed conversions km/m, kg/g and hours/minutes. Decimal arithmetic uses precision 60 and exact comparison without hidden tolerance. Division by zero, unsupported units and invalid numbers are unavailable checks. A general natural-language parser is not claimed. Only the anchored total/addition and percentage-increase grammars can verify a complete arithmetic claim automatically; other calculations must use the structured job field.

Ollama analysis checks the full claim and submitted result against a bounded set of excerpts, requesting direct/indirect/insufficient/contradictory/inconclusive relations and exact quotes. A response with invented quotes is rejected. One inference call per job is currently sufficient; the configurable maximum acts as a ceiling and zero disables calls. Missing Ollama/model, malformed responses and absent usable sources produce explicit missing-analysis evidence.

Contradiction search examines **submitted sources only**, with an independent detector for conflicting `Metric = Value` lines and the semantic comparison across sources. Context-free numeric conflicts force insufficient evidence; a grounded semantic contradiction or reproduced arithmetic mismatch can yield CONTRADICTED. No web-wide independent discovery or advanced entity/period normalization is claimed in this MVP.

Decision precedence: failed calculation/semantic contradiction → CONTRADICTED; ambiguous metric conflict → INSUFFICIENT_EVIDENCE; complete matching pure arithmetic → VERIFIED; missing usable sources/analysis → INSUFFICIENT_EVIDENCE; full direct support and no failed/unavailable required calculations → VERIFIED; partial or indirect support → PARTIALLY_VERIFIED; explicit insufficiency → INSUFFICIENT_EVIDENCE; otherwise UNVERIFIED. A high score never overrides a contradiction.

Default weight percentages: accessibility 15, source support 30, numerical reproduction 25, analysis 20, contradiction search 10. Each component is 0..100 or null for not applicable. Remove null components from the denominator and take the integer floor of the weighted mean. If the denominator is zero, score is zero. Successfully reproduced arithmetic receives full numerical credit whether it matches or disproves the submitted result. Confidence is verification strength, **not probability of truth**; a strongly checked false claim may have a high score alongside CONTRADICTED. Component scoring is transparent in verdict.json and does not use an unsupported accuracy metric.

`replay` checks the original signed evidence, reloads the saved job and recomputes numerical checks with version `numerical-1`. It performs no network or inference calls and reports differing saved/current structures or exact filenames with mismatching hashes. Source contents and model outputs are preserved for inspection, but semantic inference is not rerun deterministically. Keep the relevant code/rules version when transferring an archive.
